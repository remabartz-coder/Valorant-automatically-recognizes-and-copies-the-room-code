# 发布准备

## 源码

1. 运行 `scripts/verify.ps1`；无交互桌面时可加 `-SkipDesktopTests`，并另行完成桌面捕获验收。
2. 检查 README、许可证和依赖版本记录。
3. 运行 `scripts/export-source.ps1`，生成允许列表中的源码、正式模型、图标、测试裁剪、依赖声明和 SHA-256 清单。
4. 检查导出目录后再上传 GitHub。导出不会初始化 Git、创建远程仓库或执行推送。

导出排除 `.deps`、构建产物、运行数据、日志、完整录屏及私人测试帧。代码采用 MIT；依赖和模型保留各自的声明。

## 二进制

当前 `package.ps1` 仅用于本地打包。`-ForPublicRelease` 会拒绝执行，直到当前已知的依赖源码和声明缺口关闭。

已补齐 MIT、ONNX Runtime 官方第三方声明、Qt Base 官方许可证及 SPDX 清单、实际 FFmpeg buildconf 和模型来源记录。但当前 BtbN FFmpeg 包含大量外部库，上游二进制资产没有提供可直接对应此构建的完整源码包。通用源码首页或仅有 LGPL 正文不足以解决该问题。

公开 EXE、DLL 或便携 ZIP 前，需要：

1. 保存匹配实际 FFmpeg DLL 的完整对应源码、所用依赖源码、补丁、构建脚本和配置，并补齐各依赖版权及许可证。
2. 根据 Qt/FFmpeg 实际采用的再分发方式，提供对应源码与必要安装/替换信息，或改用已核验的依赖构建与分发材料。
3. 核对 VC Runtime 的再分发范围和实际打包文件，记录构建版本与来源。
4. 为安装依赖提供长期可获取的固定哈希归档，替换有保留期限的日构建来源；同步更新脚本、来源记录和 CI 镜像配置。
5. 在干净 Windows 环境验证打包目录，执行真实直播与游戏输入验收，检查日志和配置中无待公开的私人信息。
6. 完成材料审阅后，修改公开打包门槛，并记录所用依赖和源码归档的哈希。不能只改一个“已完成”标志来跳过缺失材料。

更多证据见 `licenses/BINARY_DISTRIBUTION.md`。此限制不阻止发布项目源码和在本机使用便携包。
