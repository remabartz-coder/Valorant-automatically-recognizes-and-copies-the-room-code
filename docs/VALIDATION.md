# 验证记录与范围

测试结果说明特定样本与环境，不代表直播准确率或抢队成功率。

## OCR 样本

- 两张原始截图裁剪：`AZI973`、`DOB453`，含容易混淆的字母 I 和 O。
- 原生录屏输入框裁剪：`KOG460`、`ZUJ215`、`TEJ065`、`EHQ220`，以及隐藏为六点的负例。宽输入框保留原像素和边距。
- 合成图覆盖码型比例、边距、多码、密集文字和高分辨率小字；合成样例不能替代真实直播验证。
- 第一张压缩截图虽然读对，最低字符概率约 0.784，低于默认 0.90，所以仍被拒绝自动输出。这是预期行为。

`tests/fixtures/README.md` 记录样本来源、裁剪和预期文字；完整录屏和截图不包含在仓库中。

## 本地录屏回放（2026-10-15）

39.309 秒、2420 × 1668 的本地录屏提取为 157 张原生画面，按 250 ms 间隔回放。使用宽输入框和整个对话框两种区域，8 组可见码均各确认一次，错误确认 0 次，并拒绝隐藏码、空白和同时双码。

| 选区 | 每帧处理时间 p50 |
| --- | --- |
| 宽输入框（590 × 78） | 约 31 ms |
| 整个对话框（1236 × 678） | 约 99 ms |

全图首次定位约 0.99–1.12 秒。这些数字不包含模型加载，也不包含直播分发延迟。仅覆盖单段录屏与本机配置，样本量不足以推出线上正确率。

## 自动检查

`scripts/verify.ps1` 顺序执行构建、CTest 和两张原始截图校验。UI 测试禁用输出，语音测试使用假播放器，输入测试不向游戏发送按键。

`window_capture` 用临时合成窗口检查像素、更新和尺寸变化，需要交互桌面。受限进程缺少捕获服务时不能完成该项。2026-10-15 的正常桌面采集验收已通过；它不是对所有窗口、浏览器后台渲染或最小化状态的保证。

发布前还需在干净 Windows 环境运行全部检查、实际直播验收与目标游戏输入兼容性测试。GitHub CI 首次运行的结果以目标仓库记录为准。
